# FAST-LIO 漂移诊断数据分析提示词

## 背景

你正在分析一个 FAST-LIO（LiDAR-Inertial Odometry）系统的漂移诊断日志。FAST-LIO 使用迭代扩展卡尔曼滤波器（IEKF）融合 LiDAR 点云和 IMU 数据进行实时定位。

系统当前存在的问题是：**长时间运行后定位会发生漂移**，需要诊断漂移发生的原因。

## 数据格式

CSV 文件路径：`Log/drift_diagnostic.csv`

### 列定义

#### 基础状态（每帧记录一次）

| 列名 | 类型 | 含义 | 单位 |
|------|------|------|------|
| timestamp | float | 帧时间（相对起始） | 秒 |
| pos_x, pos_y, pos_z | float | EKF 估计位置（世界系） | 米 |
| rot_x, rot_y, rot_z | float | 旋转角（SO3 的李代数表示） | 弧度 |
| vel_x, vel_y, vel_z | float | 速度 | 米/秒 |
| bg_x, bg_y, bg_z | float | 陀螺仪 bias 估计 | 弧度/秒 |
| ba_x, ba_y, ba_z | float | 加速度计 bias 估计 | 米/秒² |
| grav_x, grav_y, grav_z | float | 重力向量估计 | 米/秒² |

#### 帧间变化量

| 列名 | 含义 |
|------|------|
| delta_pos_x/y/z | 本帧相对上一帧的位置变化量（米） |
| delta_rot_x/y/z | 本帧相对上一帧的旋转变化量（弧度，李代数） |

#### 协方差矩阵 P 的对角线（23 维）

P 是 23x23 的状态协方差矩阵，**对角线值越小，EKF 越自信**。

P 的 23 个对角线元素按以下顺序排列（列名 P_d0 到 P_d22）：

| 列名 | 对应状态 | 正常范围参考 |
|---|---|---|
| P_d0, P_d1, P_d2 | 位置不确定性 (pos) | 初始 ~100，收敛后 ~0.01-0.1 |
| P_d3, P_d4, P_d5 | 旋转不确定性 (rot) | 初始 ~1，收敛后 ~0.001-0.01 |
| P_d6, P_d7, P_d8 | 速度不确定性 (vel) | 初始 ~100，收敛后 ~0.01-0.1 |
| P_d9, P_d10, P_d11 | 陀螺仪 bias 不确定性 (bg) | 收敛后 ~1e-6 ~ 1e-4 |
| P_d12, P_d13, P_d14 | 加速度计 bias 不确定性 (ba) | 收敛后 ~1e-5 ~ 1e-3 |
| P_d15, P_d16, P_d17 | 重力估计不确定性 (grav) | 收敛后 ~1e-5 ~ 1e-3 |
| P_d18, P_d19, P_d20 | 外参旋转不确定性 (ext_rot) | 收敛后 ~1e-6 ~ 1e-4 |
| P_d21, P_d22 | 外参平移不确定性 (ext_t，前2维) | 收敛后 ~1e-6 ~ 1e-4 |

#### 匹配统计

| 列名 | 含义 | 为什么重要 |
|---|---|---|
| effct_feat_num | 有效匹配特征数 | 少 → 约束不足 → 容易漂移 |
| feats_down_size | 降采样后总点数 | 匹配率 = effct/feats_down |
| res_mean | 平均点到平面残差 | 突然变大 → 可能定位异常 |
| icp_time | EKF 更新耗时 | 异常长 → 可能退化场景 |
| kdtree_size | 局部 ikd-Tree 点数 | 太小 → 约束不足 |

## 分析任务

请完成以下分析，用 Python (pandas + matplotlib) 生成图表和结论：

### 1. 基础轨迹分析
- 画 2D 轨迹图 (pos_x vs pos_y)
- 画 pos_z 随时间变化（看高度跳变）
- 计算总行程距离

### 2. 漂移检测
- 画 delta_pos 的模 `sqrt(dx²+dy²+dz²)` 随时间变化，标注异常跳变点
- 画 delta_rot 的模随时间变化
- 检测 delta_pos 突然 > 某阈值（比如 0.5m/帧）的时刻 → 可能是 EKF 被拉回或漂移突变

### 3. P 矩阵分析（核心）
- 画 P_pos 的 3 个对角线值（P_pos_x/y/z）随时间变化
- 画 P_rot 的 3 个对角线值随时间变化
- **关键问题**：P 值是否在某个时刻突然被压到非常小？如果位置对应的 P < 0.001，EKF 几乎不可能被外部观测修正
- 对比 P_pos 和 delta_pos 的关系：P 很小的时候，delta_pos 是否出现系统性偏差？

### 4. IMU Bias 分析
- 画 bg 和 ba 随时间变化
- bias 是否有持续增长的趋势？如果有，可能是漂移的因或果
- bias 变化率突然增大 → 可能是退化场景（如沿着长走廊直线运动）

### 5. 匹配质量分析
- 画 effct_feat_num 和匹配率 (effct/feats_down) 随时间变化
- 画 res_mean 随时间变化
- 匹配率突然下降 → 可能进入了地图覆盖不足的区域
- res_mean 突然增大 → 匹配质量退化

### 6. 综合诊断
综合以上分析，给出：
- 漂移大约在什么时刻开始？
- 漂移时的各项指标特征（P、bias、匹配率、残差各是什么状态）
- 最可能的漂移原因假设

### 可能的漂移原因对照表

| 现象 | 可能原因 |
|---|---|
| P_pos 被压到极低 + 位置持续偏移 | EKF 过度自信，局部地图自我确认 |
| 匹配率骤降 + res_mean 飙升 | 退化场景（走廊、空旷区域） |
| bias 持续单向增长 | IMU 积分误差累积 |
| delta_pos 出现周期性跳变 | 全局重定位拉回（如果有外部定位） |
| kdtree_size 很小 + 特征少 | 初始阶段或 FOV 内无结构 |
| P_vel 很高 + 速度估计不稳定 | 加速度测量退化或外参不准 |
